The household planner that lives on your wall.

Marplanner turns a tablet in the kitchen into the family's shared screen: calendar, chores with streaks, meals, reminders, and a printed morning briefing for every child.

Features

Everything the family needs, on one screen

Home, Calendar, Chores and Meals for everyone. Settings, members, content and recovery live in an admin area behind a PIN. Optional features are plugins you switch on when you need them.

🧾

A printed morning briefing for every child

A cheap Bluetooth thermal printer next to the tablet prints a personal slip each morning: their events, meals, weather, reminders, a note from a parent, birthday countdowns and chore streaks.

Plus the fun part: dad jokes, word of the day, trivia, an upside-down riddle, a word search and a drawing prompt. More than 20 block types.

  • You choose who gets one, on which weekdays, with which blocks
  • It can print itself once the morning chores are done
  • No print server or drivers: ESC/POS straight over Web Bluetooth
✅

Routines & chores with streaks

Emoji chores grouped by part of the day, assigned to each child on chosen weekdays. Ticking a block off plays a little jingle and keeps the streak alive.

🍽️

Meals & recipes

A recipe catalogue, repeating weekly plans and one-off meals, merged into one menu.

📅

Shared calendar

Local events plus ICS feeds from school or work, assigned to members automatically and decorated with emoji.

🧩

Admin behind a PIN, features as plugins

Members, content, integrations and recovery. Turn on only what your household uses.

🔔

Reminders & daily messages

Scheduled reminders on the wall and a message from a parent for each child, every day.

🌤️

Weather, no API key

Today's forecast from Open-Meteo, on the screen and on the printed slip.

🗣️

Spoken time

The tablet says the time out loud at the moments that matter: 08:15, shoes on!

📵

Screen-time switch

Block or restore a device's internet access from the admin area. Handy at dinner time (UniFi).

💾

Backups & restore

Snapshots of the single SQLite database, downloadable and restorable from the admin.

🌍

English & Spanish

The whole interface, and the printed briefing, in either language.

Run it

From demo to your own kitchen

One Node.js server and one SQLite file. Try it in the cloud, then run it at home with Docker or straight from source.

Each button creates your own instance on that host, seeded with a sample family. Nobody runs a shared demo.

It is a demo, not a household install. Anyone who knows these defaults can open it. For real use, set your own credentials on fresh storage, as the Docker and Node.js tabs show.

Docker Engine and Docker Compose. From a clone of the repository:

cp infra/docker/.env.example infra/docker/.env.local
# Fill MP_ACCESS_TOKEN (mpg- prefix), MP_BOOTSTRAP_KEY (mpk- prefix), MP_ADMIN_PIN.
docker compose --env-file infra/docker/.env.local -f infra/docker/compose.yaml -p marplanner-home up --build -d
docker compose --env-file infra/docker/.env.local -f infra/docker/compose.yaml -p marplanner-home port marplanner 3000

The image runs as a non-root user and keeps SQLite and backups in /data. Container operations cover HTTPS, upgrades and subpath hosting.

Node.js 24 and a writable, persistent data directory:

git clone https://github.com/diegomarino/marplanner.git && cd marplanner
npm ci
npm run build
cp .env.example .env.local   # then replace every sample value
DATA_DIR=/path/to/persistent/marplanner npm start

The server listens on 0.0.0.0:3000 and fails closed until you configure its credentials. Read security before exposing it beyond your home network.

For developers

API-first: the tablet is just another client

The kiosk and the admin screens use the same documented HTTP API you can script against. Tick off a chore from Home Assistant, add events from cron, or show tonight's dinner on your own dashboard. 

# Provision a device once, with the bootstrap key
curl -c jar.txt -X POST "$BASE/api/auth/provision" \
  -H "Authorization: Bearer $MP_BOOTSTRAP_KEY"

# Then call any route with its device cookie
curl -b jar.txt "$BASE/api/members"
curl -b jar.txt "$BASE/api/chores/board?date=$TODAY"
curl -b jar.txt "$BASE/api/calendar/events?from=$TODAY&to=$TOMORROW"
  • OpenAPI 3.1, generated from the code. Every route declares its schema next to its handler, and CI fails if the document drifts.
  • Closed by default. Every request is authenticated and checked against domain:verb permissions.
  • Also on your instance. Each server serves its own interactive reference at /api/docs/.
