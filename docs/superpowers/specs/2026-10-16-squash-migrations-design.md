# Squash the Drizzle migrations into one baseline — design

Date: 2026-10-16. Owner request: collapse `drizzle/` into a single baseline with no deltas.
Brainstormed autonomously (owner asked for no questions); every decision below is the
worker's call unless marked as the owner's.

## Intent

`drizzle/` holds `0000_current_baseline.sql` plus five forward deltas (`0001`..`0005`). v2 has
no installed database with real data (owner), so the deltas carry upgrade machinery nobody
needs: a STRICT table rebuild, a temp-table lineage classifier, a colour remap, and the
`prior_baseline` lineage. One baseline, generated from the TypeScript schema, replaces them.

## Goals

- `drizzle/` contains exactly one migration, generated by `drizzle-kit generate` from
  `src/server/db/schema.ts`, with the few hand additions listed below.
- A fresh `DATA_DIR` reaches the same schema and fixed rows as today's `0000..0005` chain:
  ten-colour `members` CHECK, `daily_briefing_optin.weekdays`, the STRICT calendar tables,
  four day periods, one `fresh` lineage row, nine inactive plugin registry rows.
- Everything that names a migration file or the baseline lineage follows: the runner, restore,
  tests, e2e fixtures, docs.

## Non-goals / anti-goals

- No upgrade path from the old lineage (owner): an existing dev database or a v2 backup made
  before this change is **unsupported**. The runner refuses it; restore rejects it as
  unsupported lineage. That must be loud, never a silent partial schema.
- No schema behaviour change beyond deleting the dead `prior_baseline` lineage value.

## Decisions

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                              |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | New file name `drizzle/0000_baseline.sql`; `0000_current_baseline.sql` and `0001..0005` are deleted. A new name makes the break explicit: a ledger holding the old sentinel never looks "up to date".                                                                                                                                                                                                 |
| D2  | Body = verbatim `drizzle-kit generate` output (same tooling as `tests/integration/database-baseline.test.ts`), then hand additions: `STRICT` on `calendar_external_sources`, `calendar_external_event_meta`, `calendar_highlight_rules` (0001 created them STRICT and tests assert it); the four `day_periods` rows; the lineage row and nine registry rows. A header comment says how to regenerate. |
| D3  | The lineage row keeps the existing temp-context handoff (`temp.plugin_lifecycle_migration_context`) so `captured_at` honours the runner's injectable `now`. The runner creates the context when the baseline is pending.                                                                                                                                                                              |
| D4  | `installation_lineage.kind` becomes `'fresh'` only; `prior_baseline` (an install that predated plugin lifecycle) can no longer occur. Registry rows are always seeded `inactive`. The table stays: seeds/ownership and restore depend on it.                                                                                                                                                          |
| D5  | Runner: baseline pending with a non-empty ledger → `Unsupported migration history.` before any snapshot or write (old dev DBs land here). Ledger claims the baseline but lifecycle metadata is incomplete → fail closed, as today.                                                                                                                                                                    |
| D6  | Restore: sentinel becomes `0000_baseline.sql`; old-lineage backups are `unsupported_lineage` with no special case.                                                                                                                                                                                                                                                                                    |
| D7  | No `drizzle/meta`: it has never existed here; the runner reads only `drizzle/*.sql`, and the equivalence test regenerates from the schema. A snapshot would drift from the hand additions.                                                                                                                                                                                                            |
| D8  | Tests that exercised a delta's data transform (0001 forward copy, 0004 colour remap, prior-baseline seeding and restore) are deleted, not ported; their constraint assertions move onto the baseline. Probe migrations in tests keep `0001_*` numbering (now the first free slot).                                                                                                                    |
| D9  | `assertWeekdayIntegrity`'s "column added by a later migration" skip is dead (one migration, every column present) and is removed.                                                                                                                                                                                                                                                                     |
| D10 | Docs get a dated note (ADR-017, database-lifecycle, backups FR-004/FR-011) stating the squash and that pre-squash dev DBs and backups are unsupported.                                                                                                                                                                                                                                                |
